Credit card fraud detection

Catching 98 frauds in 56,962 transactions, and what each model costs

A notebook study that compares ten ways of handling a 577:1 class imbalance (class weights, SMOTE, undersampling, SMOTEENN) across logistic regression, random forest, XGBoost and a small neural network. This page lets you compare them and re-price the outcome under your own cost assumptions.

Saved results, read-only. Every number here was printed by the repo's notebook (credit_card_fraud_detection.ipynb) or its README. No model is run in your browser, and no transaction data is included. The data is the public, anonymised Kaggle "Credit Card Fraud Detection" set (European cardholders, September 2013).

Business impact: price the errors yourself

The README values the best model at a $9,811 net benefit: fraud prevented minus investigation cost. That arithmetic uses only the confusion-matrix counts, so it can be re-run for every model and for different assumptions. The defaults below are the notebook's own: $122.21 mean fraud amount (from the notebook's saved Amount statistics) and a $2.00 cost to investigate one flagged transaction. The sliders change assumptions, not data.

Notebook default: $122.21, the mean of the 492 fraud rows.
Notebook default: $2.00, charged for every flagged transaction (true and false alarms).
Not in the notebook (default $0). Use it to model customer friction from wrongly blocked cards.

Net benefit = TP × fraud amount − (TP + FP) × investigation cost − FP × extra false-alarm cost. Missed fraud is not subtracted separately; it is simply fraud that was not prevented, so the ranking is the same either way. At the defaults, XGBoost (Balanced) gives 82 × 122.21 − 105 × 2.00 = $9,811, matching the README. Note that at these defaults XGBoost (Balanced) is not the highest on this dollar view: a $2 investigation is cheap next to a $122 fraud, so high-recall models that flag a few hundred extra transactions edge it out. Raise the investigation or false-alarm cost and the order shifts back toward the precise models.

How the study works

  1. Split80/20 stratified split. 227,845 train, 56,962 test, with 394 and 98 frauds. RobustScaler fitted on the training set.
  2. RebalanceOriginal data, SMOTE (227,451 per class), undersampling (394 per class), SMOTEENN, or class weights.
  3. ModelLogistic regression, random forest (100 trees, depth 10), XGBoost (100 trees, depth 6), MLP (100, 50).
  4. JudgeAUC-PR first, then precision, recall, F1, and a dollar view from the confusion matrix.

Read this before quoting the numbers

  • One random split with only 98 fraud cases in the test set. One more or fewer caught fraud moves recall by about one point, so small gaps (for example XGBoost 0.866 vs XGBoost + SMOTE 0.856 AUC-PR) are not established differences. The notebook does not report confidence intervals.
  • The split is random, not time-ordered. The README mentions cross-validation and temporal validation, but neither appears in the notebook's saved outputs, so this page does not report any.
  • Results are at the default 0.5 threshold. The notebook did not save per-transaction scores, only plotted curves, so there is no threshold slider here. A threshold view would need the notebook re-run.
  • The dollar view applies the average fraud amount of the whole dataset to the test set, and the $2 investigation cost is the notebook's illustrative assumption, not data.
  • The notebook's business-impact cell has no saved output; the $9,811 figure comes from the README, and the confusion-matrix counts behind it (82 caught, 23 false alarms) match the saved XGBoost output.
